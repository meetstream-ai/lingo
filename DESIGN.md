# Lingo interface conventions

Lingo helps participants read and retain multilingual meeting conversations. The existing blue/navy visual system remains the design authority. This update changes the product name and refines the incumbent interface, rather than replacing its layout or visual world.

Use navy #14234a for primary text, blue #274ad9 for actions, slate #526179 for supporting copy, white work surfaces and #f6f8fb for the page. Keep visible keyboard focus. Controls share a 44px minimum target, labeled native form elements, reserved space for dropdown arrows and explicit disabled/loading/error feedback. The smiling caption mark remains an unfilled curved stroke.

Group provider roles together: speech recognition, text translation, post-call transcript and spoken language. Keep provider branding accurate even though the product is Lingo. Use “Meeting health” for the accessible view and put raw latency/quality evidence under technical details. Do not imply a provider is verified merely because credentials were saved.

Homepage sections stay compact; preserve the existing content and illustration, including its sample label. On narrow screens stack content, allow controls to wrap, and prevent horizontal scrolling. The extension popup has an explicit 360px viewport width; never derive it from its initially tiny browser viewport.

Spoken-language changes require explicit confirmation because they interrupt recording. Explain the gap and possible bot admission before submission. Preserve each part's provenance and timestamps; never pretend the restarted recording is uninterrupted. A visible previous/next-part navigation connects artifacts. The extension follows only a server-issued continuation in the same meeting room using its private background grant.
