# Lingua 1.7 audit · 23 October 2026

## Fixed

- All meeting creation paths now use the same URL validation and normalization as the extension and calendar matching. Previously the website accepted provider homepages and malformed links which the extension later rejected.
- Google Meet accepts both invitation `/<code>` and in-call `/meet/<code>` URLs. Zoom accepts numeric `/j/`, `/s/`, `/w/`, `/wc/<id>/join`, `/wc/<id>/start` and `/wc/join/<id>` paths, and sends a `/j/<id>` invitation to the bot. Passcodes and other invitation parameters remain intact.
- Teams supports modern numeric `/meet/<id>` invitations and legacy encoded `/l/meetup-join/<thread>/0` links. Business `teams.microsoft.com` and `teams.cloud.microsoft` hosts match; consumer `teams.live.com` remains separate. Tracking parameters, query order and equivalent percent encoding no longer split the same room into different identities. The bot receives the business invitation hostname; the extension can run on the cloud hostname.
- Unsupported homepages, generic Teams app/chat pages, unsafe/lookalike hosts, credentials embedded in URLs and custom ports are rejected before a bot job is queued. Zoom personal `/my/` links need the numeric invitation from meeting details; generic Teams app URLs need the original invitation. These are explicit limitations, not silent guesses or arbitrary redirect fetching.
- Extension translation choices now respect failed connection checks, matching the website. Language-switch progress is no longer overwritten by the generic recording status.
- Recording details display the human-readable post-call provider and describe re-transcription correctly. The popup displays its installed version to help identify outdated copies.
- The sample replay explicitly uses its handwritten catalog, so configuring only DeepL does not make Hindi/Tamil samples depend on that provider’s target list.

## Additional translation providers

**DeepL is implemented** as an optional fourth text translator. Save its key in Connections or `DEEPL_API_KEY`; Free keys ending `:fx` use `api-free.deepl.com`, other keys use the Pro host. Requests use server-side header authentication, automatic detection when source is omitted, explicit language validation, a 128 KiB body limit, and a terminal quota-exhausted error. Default targets use English US, Brazilian Portuguese and Simplified Chinese for the generic en/pt/zh codes.

The adapter exposes a deliberately conservative 32-code subset evidenced by DeepL’s published OpenAPI glossary target-language enum. This is not a claim that DeepL’s complete current text catalog has only 32 languages. A larger language catalog should be obtained from the account’s current languages API and verified before expanding this adapter. Hindi/Tamil targets are not exposed in this subset; Google, Azure and JigsawStack remain the configured paths for those pairs. No DeepL credential was available for real account acceptance, and no account/key was created.

**Amazon Translate is a relevant next adapter**, with documented Hindi and Tamil support. It needs an AWS account, regional configuration and IAM credentials/permissions; source `auto` also uses Amazon Comprehend and requires a supported region. It was researched, not implemented. The project already has multiple working broad-language adapters, so no custom AWS request-signing implementation or additional SDK was added in this pass.

## Verification and remaining acceptance

Final checks: 82 backend tests passed; 75 browser tests passed across Chromium, Firefox and WebKit, with 12 intentional skips for Chromium-only extension tests in the other engines. Popup and translated-overlay screenshots were inspected. The distributable build passed.

Backend checks cover provider authentication/endpoint routing, quota handling, credential privacy, preflight, URL normalization, passcode preservation, domain separation and rejection of invalid links. Browser checks cover the new provider and existing captions, transcripts, summaries, navigation, forms and accessibility. A loaded MV3 extension is tested against controlled Google Meet, Zoom and Teams HTML fixtures, including cloud redirects and translated overlays. Those fixtures do not establish real provider quality or prove that each vendor will admit a bot.

The dependency audit reports zero known vulnerabilities. The Docker daemon was unavailable, so no fresh container smoke test is claimed. The Dockerfile includes the shared parser required by the server.

Real end-to-end acceptance with live speech, host admission and post-call artifacts remains separate. The interrupted Chrome test from 22 October did not establish those outcomes. No claim of a successful live-call run is made by this audit. Provider quotas, keys, host permissions and supported MeetStream behavior still need testing with the deployment’s real accounts. Reload the installed unpacked extension (from the updated folder) for the new version and Teams cloud host support.
